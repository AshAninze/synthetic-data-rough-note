Synthetic Data for the NHP Model

An Internship Project at The Strategy Unit, NHS

Ashionye Aninze

Jul 24, 2025

Introduction

The Challenge of Healthcare Data

  • Real patient data is sensitive and highly restricted.
  • This makes sharing and collaboration difficult.
  • The NHP model is open source, but the data is a blocker.

Why Synthetic Data?

  • Privacy: Protects patient confidentiality.
  • Accessibility: Enables broader research and testing.
  • Reproducibility: Allows anyone to run and verify the model.
  • Bias Mitigation: Opportunity to create fairer datasets.

Current NHS Artificial Data Limitations

Problem: Lost Relationships

  • The existing NHS artificial data excels at privacy.
  • However, it struggles to preserve complex relationships between attributes.
  • Example: It might tell you “how many 49-year-olds” and “how many females,” but not “how many 49-year-old females with diabetes in a specific postcode.”

Impact on NHP Model

  • NHP model relies on multivariate relationships for accurate demand prediction.
  • Without these, models trained on current artificial data would be inaccurate.
  • Obstacle to identifying which patients are candidates for a mitigator.

The Consequence

  • The inability to simulate real-world interventions makes the output for demand prediction unreliable and invalid.

The Solution

My Project’s Approach

  • Use the existing Hospital Episode Statistics HES artificial data.
  • Enhance the artificial data by creating relationships needed for the NHP model.
  • This will create a useable dataset for demand prediction and for the effective assignment of mitigators.

Methodology

Approach

  • This project will use a data enhancement methodology to address the limitations of the existing artificial HES data.
  • Rather than generating a new dataset from scratch, the approach is to add relationships to the existing 10,000-row artificial dataset.
  • This provides a practical solution that is capable of being done within the project timeline and stands by the requirement of not using real HES data.

Input Data

The project will use the existing, non-disclosive 10,000-row artificial HES dataset created by NHS England.

Process

The process for enhancing the artificial dataset will follow these key steps:

  1. Initial Data Validation: The project began by validating the current state of the artificial data. A correlation matrix was generated in Python, which confirmed the lack of meaningful linear relationships between numerical attributes, thereby justifying the need for this enhancement project.
  1. Relationship Identification: Based on the requirements of the NHP demand model, a defined set of key inter-column relationships will be identified. These are the specific relationships that are crucial for the model’s accuracy and for the assignment of mitigators.

  1. Data Enhancement: Using Python and the Pandas library, a script will be developed to create realistic relationships into the artificial dataset.

  2. Output and Validation: The final output will be an enhanced artificial HES dataset. This dataset will be validated to confirm that the newly created relationships are present while also ensuring the data remains non-disclosive and suitable for the open-source NHP model.
